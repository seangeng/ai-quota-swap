# Changelog

## 0.1.0

The first release under the name ai-quota-swap, and the first on PyPI. The project started as a fork of [claude-swap](https://github.com/realiti4/claude-swap) 1.1.0b1, and everything that version did still works: switching Claude Code accounts by hand or automatically, parallel sessions with `run`, the dashboard, the macOS menu bar, JSON output, export and import.

The package is `ai-quota-swap` and the command `qswap`. Install it with `uv tool install 'ai-quota-swap[menubar]'` on a Mac, or `uv tool install ai-quota-swap` on Linux and Windows. It keeps its own data directory, Keychain service, LaunchAgent and environment variables (`AI_QUOTA_SWAP_NO_BUNDLE`), so it installs beside claude-swap. Accounts move across with `cswap export` and `qswap import`.

### Command line

- `qswap --help` is a map of the commands grouped by task; every verb has its own `--help`, and `qswap help VERB` prints it. Bare `qswap` off a terminal prints a three-line hint.
- `qswap doctor` checks Claude Code, Codex, the data directory, the saved-login store, the macOS menu bar service and install location, and auto-switch, and says how to fix anything that is not right. `--json`, and `--online` for network checks.
- One wording everywhere: accounts are `#2 work`; an account the tool will not use until its owner logs in again is `needs re-login` (in `list`, `status`, the auto log and `--json` as `needsRelogin`); a failed reading is `usage unavailable (HTTP 503), retrying`; an old one `as of 3h 5m ago`.
- `list` and `status` share one account block, coloured by severity (yellow from the account's switch line, red at the limit, which is also said in words). `status` covers Claude Code and Codex and says whether auto-switch is running.
- `qswap auto` prints one line per check, in words, and lists the other accounts when a switch is being decided (`--verbose`: on every check).
- `switch N` refuses an account that needs re-login unless `--anyway` (which only overrides that refusal; `--force` keeps its meaning), and warns before switching to one whose usage cannot be read or is old. A rotation (`switch` with no account, `--strategy best` or `next-available`, `qswap codex switch`) skips such accounts, one line each, as it skips disabled ones.
- Read-only commands never ask; a question is only asked on a terminal, and without one the command stops with a line naming `--yes` (now on `remove`, `purge`, `add --slot`, `add-token --slot` and `qswap codex remove`). Cancelling `purge` changes nothing, the menu bar included.
- Usage errors exit 64 (not 2, which `auto --once` uses for "nothing to do"); every `--json` failure is the error envelope, and every payload carries `schemaVersion`. `priority --json` is new.
- Messages fit 80 columns and name commands by verb, never by a legacy flag. `qswap budget` and `qswap api org` output are not yet wrapped or worded this way.
- `qswap upgrade` names the build before and after, with the commit of a git install, so a new commit of the same version reads as an upgrade (`ai-quota-swap upgraded: 0.1.0 (ad03d17) -> 0.1.0 (fdeb279)`) and no change as `ai-quota-swap is still at 0.1.0 (fdeb279).`; `qswap --version` adds the commit too (`qswap 0.1.0 (fdeb279)`). A PyPI install has no commit and shows the version alone.

### Dashboard

- Claude Code and Codex accounts in one dashboard, a section each, with each provider's active account in full; the watch page, the switch picker and the disable and remove menus list both, and every action goes to the account's own provider.
- A card says what `qswap list` says, in the same order and words (`needs re-login` with its next step, `usage unavailable (HTTP 503), retrying`, `as of 3h ago`, held resets as a sentence, `extra` for extra-usage spend), coloured by the account's own switch line.
- A cost line under the title (today and the last 7 days, estimated at API prices), and a usage screen (`u`): the `qswap usage` report, regrouped with Tab, 7 or 30 days with `d`.
- The auto view runs one engine per provider, hosted as the menu bar hosts them, each with its own badge (`OFF`, `DRY-RUN`, `LIVE`), line and toggle (Tab between them, or side by side from 140 columns); "Next best" lists only what the engine would consider.
- A first run says how to log in or offers `Add <email>` first; the add menu lists what each provider can add, `qswap codex login` included. No menu offers an action that cannot work.
- Nothing wraps at 80 columns: emails give way before aliases and plans before figures, and a crowded screen keeps every account on one line before it folds any.
- Switching to an account that needs re-login is refused with the command line's message and a "Switch anyway" choice; removing asks what `qswap remove` asks. Errors read as on the command line, never as a traceback. `esc` goes back on every screen, and `q` quits from every screen outside a dialog.
- The dashboard and the command line have qswap's own colours: a violet accent on cool ink backgrounds, in dark and light.

### Codex (experimental)

- `qswap codex add`, `list`, `status`, `switch`, `remove`, `alias`, `disable`, `enable`, `threshold` and `priority` keep several Codex CLI logins and switch between them.
- `qswap codex login` logs another account in under a temporary Codex home, so the login in use is never signed out.
- `qswap list` shows a Codex section with live usage, and `list --json` adds `providers.codex`.
- `qswap codex auto` runs the shared auto-switch engine over Codex accounts and switches only once the active account is out (`codex.threshold`, default 99), because a switch restarts Codex's background server.
- `qswap codex reset` lists and spends Codex reset credits, and auto mode spends them under the same `resets.*` settings as Claude.
- qswap never refreshes a Codex login and never runs `codex logout`. Tested against fakes and with one real account; not yet run with two real Codex accounts.

### Menu bar (macOS)

- Codex accounts get a section of their own once Codex manages one; clicking a row switches that provider, and the add, disable and remove menus cover both, named with their provider.
- One auto-switch toggle per provider (*Auto-switch Claude Code*, *Auto-switch Codex*), each hosting that provider's engine in its own thread with its own settings (`codex.threshold` for Codex). The first row says, in words, which engines run; *Settings → Title follows* puts Claude Code's, Codex's or the closest-to-its-limit account in the title.
- Account rows are short (`#1 personal · 5h 46% · 7d 38% · 1 Fable reset`, at most 72 characters): a countdown only once a window is at its limit, orange from the switch line, the full `qswap list` block as the tooltip. Rows and notifications use the command line's words: `#2 work`, `needs re-login` (also for an account the engine set aside), `usage unavailable (HTTP 503), retrying`, `as of 3h 5m ago`, `extra`, API-key spend. Notifications are titled `ai-quota-swap` and say each thing once, across both engines.
- A cost row, `Today $17.21 · 7 days $180.55 (estimated)`, from the ledger, which the menu bar scans in the background every 15 minutes.
- Adding from a token is one dialog (token, optional email, setup-token or API key); removing asks what `qswap remove` asks; switching to an account that needs re-login asks first with `qswap switch`'s explanation.
- `menubar_settings.json` gains `codex_auto_switch_enabled` and `title_follows`; an older file loads as before, and keys a build does not know are kept.
- The menu is described by one pure function (`menubar.build_menu`) and drawn by a thin rumps layer; `scripts/demo/run.py SCENARIO --menubar` prints it.
- First-day polish: an unused API-key account reads `no usage recorded` (`$0 of $500 this month` with a budget) the same before and after the ledger's first scan; placeholder names show as `#5 api-key-5` wherever an account is named; held resets of several kinds read `resets: 3 Fable, 1 weekly`; `qswap import` over the active login says nothing needs doing; *Settings → Use resets automatically* sets `resets.auto`, `resets.weeklyForModelLimit` and `resets.beforeSwitch`; *Use a reset* spends one by hand through the same sequence as `qswap reset N --grant ID`, reserved under the state lock like the engine's claims. A reset whose outcome is unknown is reported as possibly used, and one the server had already counted as used, never as not used, in the menu bar and by `qswap reset`; an API-key account whose usage ledger cannot be read shows `spend unknown`, never $0, and `qswap usage` rebuilds a ledger file that is not a database.
- The menu bar is tested through `build_menu` and unit tests.

### Usage and cost

- `qswap usage` reports tokens and an estimated cost at API prices from the session files Claude Code and Codex write, by day, account, model, project, provider or session. It runs locally and stores no message content.
- The price table is copied from the vendors' published pages; `pricing.json` overrides it.
- An activation log records which account was active when, so usage is attributed to accounts.
- A report reads only the session files its date range needs.

### Usage resets

- `qswap reset` lists every account's usage resets and spends one. `qswap list` and the dashboard say what an account holds ("Holds 1 Fable reset"), and the menu bar shows a notification.
- A dry run that would spend a reset says so and stops there, rather than also reporting a switch.
- The auto-switch engine spends resets under `resets.auto` (`last-resort` by default, or `active`, `on-limit`, `off`), only on a fresh reading, at most 3 a day for each provider, with a request id that makes a retry safe.
- Resets have kinds (Fable or another model, 5-hour, weekly, full), read from the windows they clear. The planner spends the narrowest one that helps, and spends a weekly or full reset on a per-model limit only when `resets.weeklyForModelLimit` allows it. JSON output gains `scope`.
- `resets.beforeSwitch` (off by default): under `resets.auto active` or `on-limit`, auto-switch stays past the switch line while the active account holds a reset of its own that auto mode spends at `resets.threshold`, and spends it there (`reset-ahead`) instead of moving at the line. The rules for spending a reset do not change; a reset auto mode would keep, one whose claim failed or was refused, and one usable only once a limit is reached do not hold the switch, and neither does an active account qswap cannot read again (no reading from the last five minutes, or a failed read since). The cost: with `resets.threshold` 100 the account is at its limit until a check reads it there and spends the reset; a `resets.threshold` at or below the switch line avoids that. Set it with `qswap config set resets.beforeSwitch true`, which says when `resets.auto` or `resets.enabled` makes it do nothing, or with the menu bar's *Use the active account's reset before switching*, greyed in those cases. With it on, setting `resets.auto` to `off` or `last-resort`, or `resets.enabled` to false, says it now does nothing.

### API accounts

- API-key account rows show spend today and this month: exact per key from Anthropic's Admin API once the organization is registered, otherwise an estimate from the local ledger, labelled as one.
- `qswap api org add`, `list` and `remove` register an organization's Admin key. It is stored like a saved login, and qswap sends only GET requests with it.
- `qswap budget` sets a monthly budget per API-key account. The engine warns at 80%, never switches to an account at its budget, and leaves an active one that reaches it.
- `qswap usage --billed` shows an organization's usage and cost as Anthropic reports them.
- `qswap switch 5` to an API-key account moves every running and new Claude Code session onto the key within a few seconds, without logging anyone out (tested on Claude Code 2.1.322 with sessions in print mode; not yet with interactive ones, nor with a claude.ai login underneath on the user settings file). qswap adds one line, `"apiKeyHelper": "<qswap> key-helper 5"`, as the first member of Claude Code's user settings, and takes it out when you leave the key; deleting it by hand is one line. The subscription stays logged in underneath (`#5 ci · active · API key · over #1 personal`; its row says `underneath`), and the switch says how to go back (`Go back with: qswap switch 1`) and that claude.ai connectors and Remote Control are unavailable while a key is in use. Nothing else changes: not the login, not the saved key, not `~/.claude.json`, and the rest of the settings file is kept byte for byte.
- A switch to a key is refused, with the fix, when the line could not work: another `apiKeyHelper` in the file, or `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or a cloud provider variable in its `env` block, which Claude Code obeys first (beside a credential, sessions would still send the key, so either could be billed, and the switch to the key already active says they still do); or a file qswap cannot parse or write, where `--log-out-sessions` takes the older saved-key way. `ANTHROPIC_BASE_URL` there gets a warning naming the host the key goes to. Under `--json` the refusal is `KeyHelperUnavailableError` (a kind of the `SessionsRunningError` this refusal used to be), with `logOutSessions: false` where that flag would not help.
- Rotation and its strategies move among subscriptions only (`--json` reason `api-key-only` when only keys are left). From a key they go back to the account underneath, pick their target before they touch the line, and stay on the key when there is nowhere to go; a failure on the way, Ctrl-C included, puts the line back. `qswap switch 5` to the active key checks its line and repairs it. `qswap run` profiles get a copy of the settings without the line while it is in. Remove, swap, move, add, add-token, export and import keep the key and the login underneath safe: `qswap add` under a key says the key is still active, and a replaced key reaches running sessions within 5 minutes.
- `qswap status`, `qswap list`, the dashboard, the menu bar and `qswap doctor` say when auto-switch entered the active key (`by auto-switch`) and when nothing watches its limit, with the way back. They report a line that names no key, a line that came back after qswap took it out (within 24 hours of that; later it is yours), a key whose line was deleted by hand (fixed by the switch to the account underneath, `qswap switch 5` to use the key again second), settings that cannot be read while a key is recorded, run profiles left with a copy or still sharing the settings, another `apiKeyHelper`, a variable in the settings' `env` block that outranks the line, and another qswap's line (for another data directory, which qswap leaves alone and names; on Linux a line that names none is this qswap's own, and `qswap switch N` to it adds `--data-dir`), each with its command. `qswap switch 5` to the active key refuses, changing nothing, while such a variable is set, and a switch to a key always names the way back, also over a login qswap does not manage. Doctor runs the line's own command with `--check`, and warns about what outranks the line: another helper, the settings' `env` block, the managed and project settings, and the shell's variables (`CLAUDE_CODE_OAUTH_TOKEN` follows a key). While a key auto-switch entered is active, status, list, the dashboard and the menu bar also name each account holding a reset auto mode keeps, with `qswap reset N`. JSON: `enteredBy` on list rows and `status`'s `active`, and `keyNotes` in `list` and `status`, one `{code, account, fix}` per note the text prints.
- `qswap key-helper N` (hidden) prints an API-key account's saved key for Claude Code and nothing else; `--check` prints nothing, and a failure is one line on standard error. `qswap help key-helper` works. `qswap run N` for an API-key account starts Claude Code on the shared profile with the helper in `--settings`, for that session only.
- With `autoswitch.includeApiKeyAccounts` on, auto-switch uses an API key only as a last resort: when the active subscription is at its limit and no other can take over, after any usage reset it would spend, and only a key with a monthly budget or a credit and a spend figure no older than 20 minutes, which it measures itself before the move and every 5 minutes on the key. Running sessions follow the move. It comes back once a subscription has 5 points of room in every window and the cooldown has passed, leaves any key at once at its budget, its credit, or with no fresh figure, never moves from key to key or over a login qswap does not manage (nor, after leaving one key at its limit for a full subscription, to another key until a subscription has room: `key-left`), and when it stops on a key it entered it says that nothing watches the key's limit now. New `no-switch` reasons: `key-no-limit`, `spend-unknown`, `reset-pending`, `limit-latched`, `key-left`, `key-unusable`, `switch-failed`, `stuck-on-key`, `settings-unreadable`.
- Auto-switch never moves to an API key while another subscription has 5 points of room in every window it watches, even one over its own switch line and with any `--strategy` (`taken over its switch line (5h 95%) before an API key`); while another subscription's usage cannot be read, the key waits up to one cooldown, or until the second check when checks are further apart (`usage-unreadable-hold`). A usage reset it spends still comes first; one your `resets.*` settings keep stays banked, and the switch onto a key names it with the reason (its window refilling within `resets.minHoursLeft` first, whatever else applies) and `qswap reset N`, in the log, the notification and JSON (`resetsKept`).
- A key linked to an organization, or one qswap cannot tell is linked because the organization's keys could not be listed, is held to Anthropic's figure only: once that figure is 20 minutes old or missing, this machine's estimate is shown (`this machine only`) but never trusted, and auto-switch reads Anthropic's figure itself before it moves to such a key and every 5 minutes on it. Auto-switch's own ledger scan reaches back to the start of the month, or of a credit recorded before it, and a scan that fails or cannot read every session file counts as no figure (a file deleted while it runs does not count; JSON `scan.vanished`), said as such (`2 session files on this machine could not be read`, with the way out) on the switch, the hold and the rows.
- A budget and a credit are latched apart: recording a credit no longer undoes a budget reached this month, nor setting a budget a spent credit. Turning `autoswitch.includeApiKeyAccounts` off takes sessions off a key auto-switch entered, also for an engine already running (the menu bar's included), which reads that setting at each check unless a flag set it. A dry run does not count as watching a key, nor hides a real engine running beside it, and a `qswap auto --once` counts for 15 minutes (`last checked 4m ago`). The dry run says that a real run measures the spend first, and checks the key's slot.
- `qswap credit N AMOUNT [--expires DATE]` records a prepaid credit that the account's spend counts down from (`$1,150 of $1,187 credit left`, `credit counted from 14:00 UTC Nov 10`); at zero or after its date auto-switch treats the account as at its budget. JSON: `apiSpend.credit` and a row field `credit`. `budget` and `credit` read amounts strictly (`1,187.03`; a bad one exits 64) and refuse an expiry date already past. A key whose budget or credit has no figure from the last 20 minutes reads `limit not enforced: no spend figure`, and tokens of a model with no price count at the dearest rate (`+`).
- `qswap usage` attributes a saved-key period only to sessions started after it and says the split is approximate, and a session started under the key line keeps its usage on the key, as does one opened just before auto-switch entered the key and stamped with the login underneath. The activation log records how each account was activated (`how`). `import --force` keeps an account's budget and credit.
- Before the key helper: switching to an API-key account no longer logs running Claude Code sessions out unasked: `qswap switch` refuses while sessions are running unless `--log-out-sessions`, rotation and auto-switch skip the account then, and the menu bar and dashboard ask first. The switch keeps MCP server sign-ins, an API-key account's saved key is never overwritten when you leave it (one already overwritten is restored from its previous copy before any switch, move, swap or export), session records qswap cannot read count as sessions running, `qswap add` never saves the login item an API-key account leaves behind, and `qswap doctor` reports an `apiKeyHelper` or an exported `ANTHROPIC_API_KEY` that overrides the active account.

### Tooling

- `providers.py` declares the contracts a provider's switcher implements, and every command builds its switcher through one factory. `ProviderError` is the base of every provider error.
- Tests run with a temporary `CODEX_HOME`, a guard on the real Codex login, and a block on outbound connections. Launchd, which a fake home does not isolate, is guarded too: `launchctl` answers "not loaded" to a read, a call that would change a service fails the test, and an audit hook refuses to start `launchctl` at all. A child process a test starts finds a stand-in `launchctl` first on `PATH`, which answers the same way and fails the test on a refusal. The child gets none of the other guards: it has the real Keychain, the network and `/Applications`, doctor's `/bin/launchctl print` reads the real launchd, and a child given a `PATH` of its own finds the real `launchctl` (`CONTRIBUTING.md`).
- CI runs the suite on Linux (Python 3.12 and 3.14), macOS and Windows, and lints with ruff.
- Publishing a GitHub release builds the package and uploads it to PyPI through trusted publishing (`.github/workflows/publish.yml`), refusing a tag that does not match the version. The sdist carries the source, the tests and the Markdown docs, not the screenshots or recordings.
- `scripts/demo/` makes screenshots, recordings and a tour of every dashboard screen from invented accounts, in a sandbox that blocks the Keychain, the network and process spawns.
- The demo harness renders an active API key (`run.py fleet --menubar -- switch 5`; a `last-resort` scenario where auto-switch moves to the key), and `CONTRIBUTING.md` describes the manual end-to-end check of the live switch against a real Claude Code, in a throwaway home with a made-up key.
- Design docs in `docs/design/`, plus `docs/architecture.md`, `CONTRIBUTING.md` and `SECURITY.md`.
- `.vscode/launch.json` is gone: its debug entries ran the tool, `purge` included, against the real home.
